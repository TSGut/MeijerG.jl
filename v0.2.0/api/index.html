Recommended API

MeijerG.meijerg — Function
meijerg(a, b, m, n, z)
meijerg(a_left, a_right, b_left, b_right, z)

Compute the Meijer G-function with automatic reduction to simpler functions and guarded handling of confluent active-pole clusters.

Overview

This is the primary public API and recommended entry point. It implements a hierarchical polyalgorithm strategy:

  1. Special-case reduction: Recognizes patterns (exponential, trigonometric, Bessel, incomplete gamma, etc.) and reduces to elementary or special functions
  2. Parameter validation: Checks for valid parameter pairings (skipped for special reductions)
  3. Log-ratio jet selection: Uses guarded exact and near-confluent active-pole log-ratio jets when their support policy selects
  4. Raw Slater expansion: Uses the separated-pole residue expansion otherwise
  5. Contour fallback: Falls back to Mellin-Barnes contour integration if Slater fails or if a residue sum cannot be certified

Every residue sum (jet series and separated Slater expansion) records its summation conditioning κ_sum = Σ|T_n| / |Σ T_n|, the digits lost to cancellation between its terms. This certificate decides between the input-precision result, an internal doubled-precision re-evaluation, and contour integration. A sum is re-evaluated when it lies off the series' convergent regime (|z| > 1 for the lower branch, |z| < 1 for the upper branch) or when κ_sum exceeds 1e2: Float32 inputs on the Float64 path, Float64 inputs in an internal double-double kernel (about five times the cost of the Float64 kernel for the exact-pair series, more for the separated Slater expansion and the finite-separation and higher-order jets), and BigFloat inputs with more bits. Contour integration remains the fallback beyond κ_sum ≈ 1e14. The returned type is unchanged by this.

Arguments

  • a, b: complete upper and lower parameter collections (tuple/vector form)
  • m, n: Meijer G indices with 0 <= m <= length(b) and 0 <= n <= length(a)
  • z: evaluation point (any Julia number type: Float64, BigFloat, Complex, etc.)

Alternative signature

The split-parameter form meijerg(a_left, a_right, b_left, b_right, z) is equivalent to meijerg((a_left..., a_right...), (b_left..., b_right...), length(b_left), length(a_left), z). This convention follows the standard notation where n = |a_left| and m = |b_left|.

Returns

The computed G-function value in the promoted floating-point type of a, b and z: real (e.g. Float64, BigFloat) when all inputs are real, complex otherwise, whichever evaluation path is taken. Supports arbitrary precision via BigFloat and complex arguments.

Examples

# Exponential: G_{0,1}^{1,0}(z | - ; 0) = exp(-z)
meijerg((), (), (0,), (), -0.5)  # ≈ exp(0.5)

# Sine: √π · G_{0,2}^{1,0}(z | - ; 1/2, 0) = sin(2√z)
sqrt(pi) * meijerg((), (), (0.5,), (0,), 0.1^2/4)

# Generic input: uses robust confluence-aware polyalgorithm
meijerg((0.3, 0.8), (0.2, 1.1), 1, 1, 0.7)

See Also

  • meijerg_slater: Pure Slater residue expansion (power users, no reductions, unsafe for confluent poles)
  • meijerg_laurent: Standalone exact-confluence Laurent/log-polynomial residue evaluator
  • meijerg_contour: Direct Mellin-Barnes integration (power users only, use explicit contour_case= to select method)

Formatter Macro

For producing human- and tool-readable representations of Meijer G-functions (plaintext, LaTeX, and Mathematica), use the @formatter macro. The macro takes a meijerg(...) call and returns a 3-tuple (plaintext, latex, mathematica).

Example:

plain, latex, math = @formatter meijerg((1,2), (3,4), 1, 1, 5)

You can also optionally pass a verbose value to disable the automatic printing.

Example:

plain, latex, math = @formatter meijerg((1,2), (3,4), 1, 1, 5) verbose=false

Pure Slater Evaluation

MeijerG.meijerg_slater — Function
meijerg_slater(a, b, m, n, z)
meijerg_slater(a_left, a_right, b_left, b_right, z)

Compute the Meijer G-function using Slater's residue expansions (DLMF §16.17).

This is the pure Slater evaluator for advanced users who want direct residue-based computation without automatic reduction to special functions or confluence handling.

Overview

The Meijer G-function is defined via a Mellin–Barnes contour integral whose residues yield finite sums of generalized hypergeometric functions (pFq). This implementation:

  • Uses the lower expansion (Slater, DLMF 16.17.2) for p < q or p = q, |z| ≤ 1
  • Uses the upper expansion (Slater, DLMF 16.17.3) for p > q or p = q, |z| > 1
  • Promotes internally to BigFloat near |z| = 1 for balanced cases to improve accuracy
  • Supports arbitrary-precision arithmetic via BigFloat and complex numbers
  • Does NOT apply reductions to special functions
  • Does NOT use log-ratio jets or Laurent residues for confluent poles
  • Does NOT certify the cancellation between its residue terms: off the convergent regime of a branch (|z| > 1 lower, |z| < 1 upper) the returned value can be inaccurate by the factor κ_sum = Σ|T| / |Σ T|. meijerg applies that certificate and a doubled-precision re-evaluation on top of this expansion

Arguments

  • a, b: complete upper and lower parameter collections (tuple or vector)
    • p = length(a) are the total upper parameters
    • q = length(b) are the total lower parameters
  • m (0 ≤ m ≤ q): number of active lower parameters (contributing residues)
  • n (0 ≤ n ≤ p): number of active upper parameters
  • z: evaluation point (Float64, BigFloat, Complex variants, nonzero)

Split-parameter form

meijerg_slater(a_left, a_right, b_left, b_right, z) is equivalent to

meijerg_slater((a_left..., a_right...), (b_left..., b_right...),
               length(b_left), length(a_left), z)

This follows the standard indexing convention where active top parameters come first, active bottom parameters come first, etc.

Log-Ratio Jet Evaluation

MeijerG.meijerg_jet — Function
meijerg_jet(a, b, m, n, z; working_precision=:auto)
meijerg_jet(a_left, a_right, b_left, b_right, z; working_precision=:auto)

Evaluate a Meijer G-function with an exact or near-confluent active-pole cluster by the log-ratio jet residue series.

This is a standalone advanced evaluator, analogous to meijerg_slater and meijerg_laurent: it performs no special-function reductions and never falls back to another algorithm. It selects the exact-pair, finite-separation or higher-order (three or four poles) jet from the pole geometry. meijerg calls the same jets with working_precision=:auto and continues to the Slater expansion or contour integration when they decline.

Working precision

Every jet series records its summation conditioning κ_sum = Σ|T_n| / |Σ T_n|, the digits lost to cancellation between its terms. The keyword decides how that is used.

  • :auto (default, the behaviour of meijerg): the series is re-evaluated in doubled working precision when it lies off its convergent regime (|z| > 1 for the lower branch, |z| < 1 for the upper branch) or when κ_sum exceeds 1e2. Float32 inputs always run on the Float64 path.
  • :input: the series is summed in the input precision only. Off the convergent regime the result can be inaccurate by the factor κ_sum, and nothing reports it.
  • :extended: the series is always summed in doubled working precision. Float32 inputs run on the Float64 path, Float64 inputs in an internal double-double kernel, and BigFloat inputs at twice the current precision(BigFloat) or more when κ_sum requires it.

The returned type is the promoted type of the inputs in every mode. Off the convergent regime a sum whose cancellation exceeds even the doubled precision is still returned.

Errors

Inputs without a cluster the jets support throw an ArgumentError. This includes p == q, separated poles, clusters of more than four poles and higher-order clusters in BigFloat (see meijerg_laurent for exact ones). A supported cluster whose series fails to converge throws an ErrorException.

Exact-Confluence Laurent Evaluation

MeijerG.meijerg_laurent — Function
meijerg_laurent(a, b, m, n, z)
meijerg_laurent(a_left, a_right, b_left, b_right, z)

Evaluate exact active-pole confluence by the Laurent/log-polynomial residue formula.

This is a standalone advanced evaluator, analogous in spirit to meijerg_slater: it performs no special-function reductions and no contour fallback. It is intended for exact lower or upper active-pole collisions where the separated Slater terms are singular but the combined Mellin-Barnes residue is finite.

Supported cases

  • lower branch (p < q) active-lower exact collisions
  • upper branch (p > q) active-upper exact collisions
  • active-pole cluster multiplicity at most four.

Unsupported inputs throw an ArgumentError rather than falling back to another algorithm. The primary meijerg dispatch uses log-ratio jets for exact and near confluence. This Laurent evaluator is kept available as an explicit residue-form diagnostic.

Contour Evaluation

MeijerG.meijerg_contour — Function
meijerg_contour(a, b, m, n, z; kwargs...)
meijerg_contour(a_left, a_right, b_left, b_right, z; kwargs...)

Evaluate the Meijer G-function by direct numerical integration of the Mellin-Barnes contour.

Warning: This is a low-level API intended for power users and validation workflows. For normal use, call meijerg() instead, which uses reductions, guarded log-ratio jets, and Slater before contour integration.

This method numerically integrates the defining contour integral using explicit DLMF contour families (DLMF 16.17):

  • Case (i): vertical Barnes contour s = σ + i t (robust when strip exists)
  • Case (ii): loop contour around lower poles of Γ(b_j - s) (DLMF Case ii)
  • Case (iii): loop contour around upper poles of Γ(1 - a_j + s) (DLMF Case iii)

By default (contour_case = :auto), case selection follows pole geometry:

  • If a separating vertical strip exists and the vertical integral converges, |arg z| < (m + n - (p + q)/2) π (DLMF 16.17(i)): Case (i), falling back to the loop contour of the branch if the quadrature fails
  • Otherwise: Case (ii) for lower mode or Case (iii) for upper mode

Keyword arguments

  • rtol: relative tolerance for quadrature and truncation refinement
  • atol: absolute tolerance for quadrature and truncation refinement
  • contour_case: one of :auto, :i, :ii, :iii
  • sigma: real part of the Barnes contour. If omitted, a default value inside the admissible strip is chosen
  • initial_halfwidth: initial truncation half-width in the t variable
  • max_truncation_steps: maximum number of half-width doublings used to resolve the infinite tails

Notes

  • Real negative z must be passed explicitly as complex (z + 0im) to select the desired branch.

Calling Conventions

meijerg, meijerg_slater, meijerg_jet, meijerg_laurent, and meijerg_contour support two calling styles:

Full-parameter form

result = meijerg(a, b, m, n, z)

where a and b are tuples or vectors of parameters.

Split-parameter form

result = meijerg(a_left, a_right, b_left, b_right, z)

Equivalent to meijerg((a_left..., a_right...), (b_left..., b_right...), length(b_left), length(a_left), z)

Working precision

Every residue sum meijerg evaluates, the confluent jet series as well as the separated Slater expansion, carries a summation condition number κ_sum = Σ|T_n| / |Σ T_n|. Roughly log10(κ_sum) digits are lost to cancellation, which happens off the convergent regime of a branch (|z| > 1 for the lower, |z| < 1 for the upper expansion). A sum that is off its convergent regime or has κ_sum > 1e2 is evaluated internally in doubled working precision: Float32 inputs on the Float64 path, Float64 inputs in an internal double-double kernel (about five times the cost of the Float64 kernel for the exact-pair series, more for the Slater expansion and the finite-separation and higher-order jets), and BigFloat inputs with more bits. Contour integration remains the fallback beyond κ_sum ≈ 1e14. The returned type is always the float-promoted input type.

meijerg((0.3,), (0.2, 1.2), 2, 1, 10.0)                            # double-double internally

meijerg_jet exposes this choice for the jet series through its working_precision keyword: :auto as in meijerg, :input for the uncertified input-precision sum, and :extended to always sum in doubled precision.
